# 검색과 출력 예산 개선 결과

**필요한 근거 세션을 모두 찾은 비율이 상위 10개 기준 58.94%에서 81.91%로 올랐습니다.**
기존 4,000바이트 CLI 출력 제한을 적용한 뒤에도 **81.91%**를 유지했습니다.
이전 CLI 결과는 **39.36%**였습니다. 같은 BM25 비교군은 두 실행 모두 **82.34%**입니다.

## 찾은 문제와 수정

영어의 `I`, `is`, `my`, `in` 같은 짧은 단어에 한국어의 짧은 검색어를 위한
부분 문자열 보완 검색을 적용하고 있었습니다. 관련 없는 단어 안에 같은 글자가
있기만 해도, 색인을 훑은 순서에 따라 검색 순위 점수가 추가됐습니다.
파일명에서도 `in`이 `learning.txt`의 일부와 일치하는 문제가 있었습니다.

본문의 한두 글자 보완 검색은 CJK 문자에 적용하도록 제한했습니다. 짧은 영어
단어는 단어 검색으로 처리하고, 파일명·제목의 부분 일치 보완에서도 제외했습니다.
`AI.md` 같은 짧은 영문 파일명은 단어 경계를 통해 계속 검색됩니다.
기존 trigram 검색, 띄어쓰기 보완, 정확한 파일명 탐색, 기억 접근 정책은 유지했습니다.

출력은 **서로 다른 문서의 출처·ref·짧은 발췌문을 먼저 확보한 뒤** 남은 공간을
발췌문에 배분하도록 바꿨습니다. 공통 원본 경로는 `source-root`에 한 번 표시합니다.
각 후보에는 ref, 줄·페이지 위치, 신뢰 정보와 필요한 기억 경고를 남깁니다.

예산이 있는 일반 출력에서는 문서당 가장 높은 순위의 청크 하나를 보여줍니다.
같은 문서의 추가 청크는 JSON과 예산 없는 출력에 남습니다. 이 방식은 반복 표시를
줄이는 대신 발췌문을 더 짧게 보여줍니다. 실제 근거는 `amem read`로 확인합니다.
MCP에도 같은 배분 방식을 적용하며, 기존 6,000바이트 제한을 유지합니다.

## 전후 비교

아래의 ‘근거 모두’는 상위 k개 세션 안에 해당 문항의 근거 세션이 전부 있다는 뜻입니다.

| 측정 항목 | 개선 전 | 개선 후 |
|---|---:|---:|
| 검색 후보에서 근거 모두 @5 | 34.89% | 72.34% |
| 검색 후보에서 근거 모두 @10 | 58.94% · 277/470문항 | 81.91% · 385/470문항 |
| CLI 출력에 근거 모두 포함 @10 | 39.36% · 185/470문항 | 81.91% · 385/470문항 |
| 검색 후보에 근거 하나 이상 @10 | 85.74% | 95.32% |
| BM25 비교군에서 근거 모두 @10 | 82.34% | 82.34% |
| CLI에 보이는 서로 다른 세션 수 평균 | 5.68개 | 13.76개 |

현재 결합 검색은 ‘근거 모두 @10’에서 BM25보다 여전히 2문항 낮습니다.
BM25보다 우수하다는 주장은 하지 않습니다.

두 실행은 같은 정제본과 문항, 목표 2,400자·겹침 240자의 청크, 후보 20개,
파일당 청크 제한과 4,000바이트 출력 제한을 사용했습니다. 평가 코드는 변경하지
않았으며, 두 결과에 같은 평가 코드의 SHA-256이 기록돼 있습니다.
전체 500문항을 각각 격리해 실행하고, 근거가 있는 470문항으로 검색 점수를 계산했습니다.
이전 결과도 그대로 보존했습니다.

이 데이터로 원인을 분석하고 수정 효과를 확인했으므로, 보지 않은 별도 데이터에서의
검증 결과는 아닙니다. 실행 경로는 동점 순위와 출력 길이에 영향을 줄 수 있습니다.
이 수치는 근거가 있는 세션의 위치를 찾는 성능이며, 최종 답변 정확도나 제한된
원문 읽기에 정답 구간이 포함되는 비율을 뜻하지 않습니다.

## 검증과 적용

영어 부분 문자열 오탐, 일반 단어 때문에 밀리던 근거의 순위, 짧은 영문 파일명,
제한된 예산 안의 여러 문서 ref, 아주 작은 출력 예산, 기억 경고 보존을 회귀 테스트에
추가했습니다. 기존 한국어 띄어쓰기·정규화·두 글자 검색, 파일명 탐색, 원본 무결성과
기억 접근 정책 테스트 및 설치된 CLI·MCP 실행 검증도 통과했습니다.

저장 구조와 추출 정책을 바꾸지 않았으므로, 기존 색인과 ref를 계속 사용할 수 있습니다.
이 수정 때문에 색인을 다시 만들 필요는 없습니다.
