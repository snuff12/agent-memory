# LongMemEval-S remeasurement: Agent Memory 0.3.0

Measured 2026-10-16 (Korea time), engine `ff1c3e1`. [한국어](V0_3_0.ko.md)

**All-evidence session retrieval @10 is 403/470 (85.74%).** The earlier published
`ea53b90` result was 385/470 (81.91%), a net gain of 18 questions or 3.83 percentage
points. A fresh same-path control of the immediate pre-0.3.0 engine `5c7fda1`
also scores 85.74%. Every per-question session ranking and retrieval metric is
identical between that control and 0.3.0 across all three evaluated systems.

The historical gain therefore predates the two 0.3.0 features. This protocol
uses default single-query retrieval, without semantic candidates or source reads;
it does not measure the new locate, line-read or semantic-window capabilities.
No benchmark-specific engine changes were made during this remeasurement.

## Results

“All evidence @k” requires every published evidence session in the first k
distinct sessions. “Any evidence” requires at least one. These are retrieval
scores, not generated-answer accuracy.

| Metric | Earlier published `ea53b90` | Fresh control `5c7fda1` | 0.3.0 `ff1c3e1` |
|---|---:|---:|---:|
| All evidence @1 | 25.53% | 24.47% | 24.47% |
| All evidence @5 | 72.34% | 77.02% | 77.02% |
| All evidence @10 | 81.91% | 85.74% | 85.74% |
| CLI-visible all evidence @10 | 81.91% | 85.74% | 85.74% |
| Any evidence @10 | 95.32% | 96.38% | 96.38% |
| Session MRR | 0.8306 | 0.8496 | 0.8496 |
| Word-only BM25 all evidence @10 | 82.34% | 85.96% | 85.96% |

Compared with the historical run, all-evidence @10 improves on 35 questions and
regresses on 17; 418 are unchanged. All-evidence @1 falls from 120 to 115
questions, so the gain is not universal. The current word-only BM25 ablation
finds all evidence on 404/470 (85.96%), one more question than the combined
retriever. Its terms come from the engine's current query planner; it is a
shared-terms word-only comparison, not a frozen independent retriever or a
reproduction of the paper's `flat-bm25`.

## Conditions and control

Both fresh runs use the unchanged `longmemeval-s-session-retrieval-v1` harness,
whose SHA-256 remains
`ad413428b1afa7c52ec2f387679b170de6a06d8cea1d72cdab8813e52a44ef80`.
The pinned cleaned S dataset, its checksum, all 500 question IDs/gold evidence,
2,400-character chunks, 240-character overlap, 20 candidates, two chunks per file
and 4,000-byte CLI output cap are unchanged. The 470 answerable questions determine
the scores; 30 abstention questions are diagnostics only. No LLM, embeddings,
query expansion or answer generation is used.

Each question gets an isolated home containing only that history; it is removed
before the next question. Completed new-version output was moved aside, then the
control ran at the exact same source-home path, and both outputs were preserved.
This controls path-derived IDs, tie ordering and provenance overhead for the
immediate-parent comparison. The historical published run used another output
path and an older query-selection/renderer implementation. This experiment does
not isolate which intervening change caused each historical gain or regression.

The historical and current engines are compared as measured revisions. Query
rules, weights, aliases, gold labels, budgets and engine code were not adjusted
after seeing these results. This remains a previously used development dataset,
not an unseen held-out evaluation. See [the protocol](README.md).

The new run took 218.653 seconds; the control took 283.522 seconds. Both indexed 23,867 session entries and 134,811 chunks, preserving 13 repeated-session-ID entries. New CLI output was at most 4000 bytes (mean 3987.6). Search latency was p50 16.721 ms and p95 31.003 ms, excluding preparation, indexing, rendering and source reads. These single-machine timings are diagnostic, not a controlled speed claim.

Per-question public output allowlists IDs, counts, session rankings, metrics and
timings; it omits raw chunk arrays, questions, expected answers, conversation
text and local paths. Each summary's `case_records_sha256` hashes its original
private `cases.jsonl`, not the compact public JSON. Public-file hashes are in
the paired-comparison artifact. Downloaded data, operational memory, indexes and
raw histories are not distributed. Historical result files remain unchanged.

To rerun the measured version, check out `ff1c3e1`, install the project, then run:

```bash
.venv/bin/python -m benchmarks.longmemeval run \
  --output "$HOME/.cache/agent-memory-benchmarks/longmemeval/new-unique-run"
```

Use the same pinned dataset and an unused output directory. For the paired
control, repeat from `5c7fda1` at the same absolute source-home path after moving
the completed output aside, then preserve both completed runs. Verify each
summary's engine and harness fingerprints. Different paths or machines may alter
ties, byte overhead or timing; do not infer equal conditions from version names alone.
