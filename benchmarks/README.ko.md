# LongMemEval-S 검색 벤치마크

[English](README.md)

별도 실사용 진단은 [qmd·HippoRAG·Graphiti·Mem0·Letta·SCIP 실제 비교](SYSTEM_COMPARISON.ko.md)를
확인하세요. 아래 LongMemEval 점수와는 다른 실험입니다.

질문에 답하는 데 필요한 **대화 세션을 찾는 능력**을 측정합니다.
LLM·API 키·GPU 없이 실행합니다. [최신 개선 결과](IMPROVEMENTS.ko.md)와
[첫 평가 결과](RESULTS.ko.md)는
고정한 LongMemEval-S 정제본 전체의 검색 결과입니다. 최종 답변 정확도는 측정하지 않습니다.

## 실행

루트 README에 따라 설치한 뒤 저장소 루트에서 실행합니다.

```bash
.venv/bin/python -m benchmarks.longmemeval download
.venv/bin/python -m benchmarks.longmemeval run \
  --output "$HOME/.cache/agent-memory-benchmarks/longmemeval/my-run"
```

출력 디렉터리는 새 경로여야 합니다. 데이터 약 277 MB를 내려받고, 한 번에
한 문항의 색인만 만듭니다. 기본 캐시는 `~/.cache/agent-memory-benchmarks/longmemeval/`이며
`XDG_CACHE_HOME`을 지원합니다. 데이터와 실행 결과는 저장소 밖에 둡니다.

`--limit 10`을 추가하면 원본 순서의 첫 10문항으로 실행을 확인합니다.
이 결과는 부분 실행으로 표시하며, 대표 표본으로 취급하지 않습니다.

## 평가 조건

| 항목 | 조건 |
|---|---|
| 데이터 | [공식 LongMemEval 정제본](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned)의 S 파일. 버전과 SHA-256 고정 |
| 문항 수 | 전체 500문항 실행. 근거가 있는 470문항으로 검색 점수 계산 |
| 나머지 30문항 | 답변을 보류해야 하는 문항. 검색 후보가 나왔다는 이유로 오답 처리하지 않음 |
| 격리 | 문항마다 새 메모리 홈을 만들고, 해당 문항의 대화 기록만 색인한 뒤 삭제 |
| 정답 누출 방지 | 질문·정답·근거 표시를 색인하지 않음. 원본의 날짜·발화자·대화 본문만 사용 |
| 청크 | 엔진의 기존 설정인 목표 2,400자, 겹침 240자 사용 |
| 검색 | 청크 후보 최대 20개, 파일당 최대 2개. 세션 ID의 중복을 제거한 뒤 순서대로 평가 |
| 모델 사용 | 임베딩·요약·질문 확장·답변 생성 없음 |

원본에는 같은 세션 ID에 서로 다른 대화가 있는 사례가 있습니다.
각 기록을 모두 보존하고, 공개된 세션 ID를 기준으로 평가합니다.
해당 기록 수는 결과에 따로 남깁니다.

## 세 가지 결과의 의미

| 이름 | 평가 대상 |
|---|---|
| `amem_candidates` | CLI 출력 제한을 적용하기 전, 엔진이 찾은 청크 후보 20개 |
| `amem_cli_4000_bytes` | 실제 CLI 형식으로 출력했을 때 4,000바이트 안에 남는 후보. 출처·경로·발췌문 포함 |
| `fts5_bm25` | 같은 청크와 단어 검색 조건에서 SQLite FTS5 BM25만 사용한 비교군 |

CLI 실험은 `amem search ... --collection research --limit 20`에 해당합니다.
기본 요청 개수인 5개 대신 20개를 요청하되, 기존 4,000바이트 출력 제한을 적용합니다.
개선한 출력은 문서마다 후보 하나를 먼저 확보하고 공통 경로를 묶은 뒤,
여유가 있으면 같은 문서의 추가 구간도 확보한 뒤, 남은 예산을 발췌문에 나눠 씁니다.
JSON에는 전체 후보가 남습니다. 과거 점수와 현재 엔진의 차이는 각 결과 문서에 표시합니다.

BM25 비교군은 여러 검색 순위를 결합하는 기능, 부분 문자열 검색 등의 영향을
분리해서 보기 위한 것입니다. 원 논문의 `flat-bm25`를 재현한 구현은 아닙니다.

| 지표 | 의미 |
|---|---|
| `session_hit@k` | 상위 k개 세션에 필요한 근거가 하나 이상 있는 문항 비율 |
| `session_all@k` | 상위 k개 세션에 필요한 근거가 **모두** 있는 문항 비율 |
| `session_recall@k` | 문항별로 필요한 근거 세션 중 찾은 비율의 평균 |
| `session_mrr` | 첫 근거가 앞쪽에 나올수록 높은 순위 점수 |

`session_all@k`는 공식 코드의 `recall_all@k`와 같은 이진 판정입니다.
우리 청크를 세션으로 묶는 방식과 후보·출력 예산은 이 저장소의 평가 조건입니다.

## 해석 범위

근거가 있는 세션을 찾았어도, 실제 답이 발췌문이나 제한된 `amem read` 결과에
포함된다고 보장하지는 않습니다. 이 결과를 답변 정확도로 읽으면 안 됩니다.
최종 답변 평가는 답변 모델·프롬프트·원문 읽기 예산·채점 모델을 고정한 별도 실행이 필요합니다.

검색 시간은 한 기기에서 문항당 한 번 측정합니다. 색인 시간은 제외합니다.
BM25 비교군은 엔진 검색 뒤에 실행하고 파일 무결성·정책 검사를 반복하지 않으므로,
시간을 단독 속도 경쟁의 근거로 쓰지 않습니다. 절대 경로가 동점 순위와 CLI 출처의
길이에 영향을 주므로, 다른 실행 경로에서는 일부 점수가 달라질 수 있습니다.

`summary.json`에는 전체·유형별 점수, 검색 시간, 출력 바이트, 환경 버전과 소스 해시를
남깁니다. `cases.jsonl`에는 문항 ID·근거 및 후보 세션 ID·청크 번호·측정값을 남깁니다.
질문·정답·대화 본문·개인 경로는 결과 파일에 넣지 않습니다.

이 저장소에는 평가 코드와 집계 결과만 올립니다. 내려받은 대화와 색인, 운영 중인
에이전트 메모리는 포함하지 않습니다. 정확한 데이터 버전과 평가식은
[영문 평가 조건](README.md)을 참고하세요.
