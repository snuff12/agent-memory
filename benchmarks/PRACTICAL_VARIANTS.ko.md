# 의미검색·그래프의 로컬 실사용 진단

[English](PRACTICAL_VARIANTS.md)

검증일: 2026-10-15. **도움이 된 사례는 있지만, 현재 시제품을 기본 검색에 넣을
근거는 부족합니다.** 이번에 준비된 의미검색 모델과 경량 그래프는 단순 후속 검색을
전체 사전 근거 검사에서 넘지 못했습니다. 모든 의미검색·그래프의 한계를 뜻하지는
않습니다.

![사전 지정 근거 확인과 현재 구현의 지연 비교](practical-variants.svg)

## 어떻게 시험했나

89개 문서, 109개 청크, 129개 임베딩 구간에 질문 42개를 사용했습니다. 38개는 사전에
근거를 정했고, 4개는 답이 없는 질문입니다. 대부분은 합성 프로젝트·운영 자료이며,
2개 질문은 실제 공개 코드 `search.py`를 검토합니다. 운영 기억은 사용하지 않았고,
질문·기대 경로·정답 표시는 인덱스에 넣지 않았습니다.

모든 방식에 검색 출력 4,000바이트와 원문 최대 3회, 매회 1,200바이트를 허용했습니다.
출처도 예산에 포함합니다. **사전 지정한 원문 구간을 모두 실제로 읽어야 통과**합니다.
문서 ID만 찾는 점수보다 엄격하지만, 답변 정확도는 아닙니다. 다른 구간의 동등한
근거를 과소평가할 수도 있습니다. LLM 답변 생성·채점은 하지 않았습니다.
실패 유형을 의도적으로 담은 작은 진단 자료이며, 일반 사용을 대표하지 않습니다.

실패에 맞춰 모델·검색어·가중치·추출기·기대 정답을 바꾸지 않았습니다. 첫 실행은
후보 20개를 표시했습니다. 그때 같은 파일의 두 번째 코드 구간이 출력 예산에서
밀려, 기존 검색이 13/38개를 통과했습니다. 권장 흐름인 후보 3개도 별도로 사전
선언해 확인했고 14/38개였습니다. 다른 방식의 합계는 같았습니다. 두 결과를 모두
보존했으며, 점수가 높다는 이유로 엔진을 바꾸지 않았습니다.

## 후보 3개에서의 결과

| 방식 | 지정 근거 모두 읽음 / 38 | 표현 차이 / 12 | 두 자료 연결 / 8 | 세 자료 연결 / 4 | 실제 코드 / 2 | 중앙값 / p95 지연, ms |
|---|---:|---:|---:|---:|---:|---:|
| 현재 어휘 검색 | 14 | 1 | 0 | 0 | 1 | 14.1 / 22.1 |
| 어휘 검색 + 원문에서 얻은 이름으로 후속 검색 | 19 | 0 | 7 | 0 | 0 | 17.1 / 28.5 |
| 기존 의미검색 시제품 | 16 | 2 | 2 | 0 | 0 | 2,006 / 2,522 |
| 어휘·의미검색 동등 비중 RRF 결합 | 15 | 2 | 1 | 0 | 0 | 2,016 / 2,535 |
| 경량 구간–개체 그래프 | 17 | 1 | 3 | 1 | 0 | 39.1 / 49.7 |
| 어휘·의미검색 + 같은 그래프 | 15 | 2 | 1 | 0 | 0 | 2,041 / 2,559 |

파일명·ID 질문 8개와 모호성·버전 질문 4개는 모든 방식이 통과했습니다. 작은 통제
사례의 결과이며 일반적인 버전·시점 추론을 증명하지 않습니다. 자동 후속 검색도
기존 유용한 후보를 밀어 두 사례가 나빠졌습니다. 이 단순 규칙을 유능한 에이전트의
최선의 탐색이라고 보지는 않습니다.

단일 어휘 검색과 비교하면 의미검색은 4개를 되찾고 2개를 놓쳤습니다. 그래프는
4개를 되찾고 실제 코드의 정의·호출부 사례를 놓쳤습니다. 후속 검색과 비교하면
의미검색은 2개 회복·5개 손실, 그래프는 2개 회복·4개 손실입니다.
[문항별 기록](results/practical-variants-top3.json)에 회복·손실 ID를 모두 담았습니다.

구체적으로 확인한 이점과 문제는 다음과 같습니다.

- **의미검색의 이점:** ‘오래된 스냅샷 복원’ 질문에서 recovery copies의 37일 보관
  규칙을 찾았고, 키보드만으로 구매하는 질문에서 마우스 없는 결제·포커스 표시
  규칙을 찾았습니다. 반면 한영 교차 표현 7개는 이 모델에서 지정 근거를 모두
  놓쳤습니다. 다른 모델도 같다는 결론은 아닙니다.
- **그래프의 이점:** Iris → Solstice → LarkQueue → 9일 보관을 연결했습니다.
  고정된 1회 후속 검색은 이 사례를 끝내지 못했습니다. 다만 두 자료 연결은
  그래프 3/8개, 더 저렴한 후속 검색 7/8개였습니다. 현재 추출기는 표시 없는
  한글 이름을 놓치고, 동명이인·공통 단어를 섞을 수 있습니다.
- **결합의 문제:** 동등 비중 RRF 결합이 정확한 코드 구간을 밀었습니다. 검색 경로를
  늘려도 정의·호출부 쌍이 보존되지 않았습니다. 문서 ID만 세면 숨겨지는 실패입니다.
- **답이 없는 질문:** 의미검색 계열은 4개 질문에서 원문을 12회 읽었고, 어휘·그래프는
  9회 읽었습니다. 불필요한 후보가 늘어난 것이며, 답변을 생성하지 않았으므로 환각
  발생률로 해석하지 않습니다.

## 속도와 메모리

현재 의미검색 시제품은 질문마다 Python·모델 프로세스를 새로 만들고 모델 파일의
해시도 검사합니다. 따라서 약 2초를 임베딩 자체의 고정 비용으로 보면 안 됩니다.
모델을 유지한 별도 시험에서는 42개 질문의 상위 3개 문서 경로가 모두 같았습니다.
OS 파일 캐시는 비우지 않았으며 동시 처리량은 측정하지 않았습니다. 새 프로세스의
시작 비용을 측정한 것이지 디스크 캐시까지 비운 비용은 아닙니다.

| 측정 | 결과 | 포함 범위 |
|---|---:|---|
| 모델 유지 시험의 시작 비용 | 1,324 ms | 라이브러리·모델·벡터 로딩 |
| 유지된 모델의 질문 처리 중앙값 / p95 | 6.5 / 8.2 ms | 임베딩·벡터 정렬만. 원본 검사·모델 해시·읽기는 제외 |
| 유지된 모델 프로세스의 최대 RSS | 1.19 GiB | 해당 시험에서 관측한 프로세스 최고 메모리 |
| 현재 의미검색의 프로세스 트리 최고 RSS | 1.36 GiB | 실행기와 모델 프로세스의 표본 측정 합계 |
| 어휘·그래프 실행 구간의 RSS | 약 30 MiB | 작은 자료·그래프를 함께 보유한 공통 실행기. 그래프의 순증가량은 아님 |

그래프 생성은 26ms, 저장 크기는 18.1KiB였습니다. 의미검색 벡터 생성은 12.4초,
저장 상태는 192KiB였고, 기존 모델 파일 약 465MiB가 별도로 필요했습니다. 이 작은
자료로 운영 규모의 비용을 추정하지 않습니다. 그래프도 매 탐색 전 허용된 원본을
검사하는 현재 구현이라, 큰 자료에서의 비용 확인이 남습니다.

첫 실행에는 메모리 표본을 다음 단계에 잘못 귀속할 수 있는 계측 문제가 있어 해당
단계별 수치를 제외했습니다. 후보 3개 실행은 이를 수정했고, 결합 방식에도 재사용한
의미검색의 시간·최고 메모리를 계산했습니다. RSS 표본은 짧은 최고치를 놓치거나
공유 페이지를 중복 계산할 수 있습니다. 방식별 순수 메모리 증가량은 분리 측정하지
않았습니다.

환경은 macOS arm64·논리 CPU 8개·코어 Python 3.9.6입니다. 모델 실행기는 Python
3.14.6, FastEmbed 0.9.0, ONNX Runtime 1.31.0, tokenizers 0.23.3, NumPy 2.5.4와
추론 스레드 4개를 사용했습니다. 추론에는 새 모델 다운로드나 LLM API를 쓰지
않았습니다. 고정된 ONNX 파일의 해시는 공식 리비전의 LFS 값과 일치했습니다.
그림용 패키지도 운영 런타임과 분리했습니다.

## 도입 판단과 남은 조건

원본 변경 거부·컬렉션 격리를 실제 추론에서 확인했습니다. 그래프는 탐색 전에
검토 상태·프로젝트·공유 범위를 다시 적용했습니다. 의미검색은 **curated memory
컬렉션을 거부**합니다. 이는 안전한 거부이며, 기억의 프로젝트·도메인·민감도 정책을
지원한다는 뜻은 아닙니다.

운영 기본 검색과 데이터는 유지합니다. 표현 차이가 있을 때 선택형 의미검색 실험과
명확한 근거 공백에 대한 후속 검색을 활용할 수 있습니다. 의미검색의 기본 도입에는
더 넓은 작업 표본, 원문 구간 전달, 무관한 질문, 모델 유지 방식, 기억 정책 검증이
필요합니다. 그래프에는 신뢰할 수 있는 개체·관계 추출과 원본 근거, 실제 규모에서
일반 후속 검색을 넘는 이득이 필요합니다. 이 진단 세트의 점수를 맞추지는 않습니다.

실험 후 코어에는 명시적인 `search '<원문 이름>' --follow-ref '<읽은 ref>'`를
[적용했습니다](../docs/retrieval-workflows.ko.md). 에이전트가 근거 공백에 필요한
원문 이름을 고르면, 엔진은 출처와 범위를 검사하고 별도 결과를 돌려줍니다.
실험의 무조건적인 이름 추출기를 쓰거나 기존 후보를 교체하지 않습니다.
위의 19/38은 이전 실험 규칙의 기록이며, 적용한 기능의 새 점수가 아닙니다.
영어·한글 연결어, 코드의 두 구간, 범위·원본 변경 검사는 별도 회귀 검증을 했습니다.

이번 그래프는 표면형 동시 출현과 Personalized PageRank를 사용한 경량 시제품입니다.
재시작 확률 0.15·반복 30회를 고정했습니다. **Graphiti·HippoRAG 2 자체를 실행한
결과가 아니며**, 사실 삼중항 추출이나 시점 추론은 없습니다.
[HippoRAG 2](https://arxiv.org/abs/2502.14802)는 설계 참고이고, 모델 사용 조건은 고정된
[E5 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small/blob/614241f622f53c4eeff9890bdc4f31cfecc418b3/README.md)를 따랐습니다.

재현 명령은 [영문 문서](PRACTICAL_VARIANTS.md#reproduce)에 있습니다.

사용했습니다. 원본 경로가 달라지면 ID 동점 순서가 달라질 수 있습니다.
