# 원문 탐색과 선택형 의미검색: 0.3 적용 기록

[외부 시스템 비교](../benchmarks/SYSTEM_COMPARISON.ko.md)에서 고른 두 개선을
실제로 구현했습니다. 기본 단어·CJK 검색은 유지합니다. 이전 비교 점수는 당시
측정한 버전의 기록이며, 이번 변경으로 새 점수를 주장하지 않습니다.

| 개선 | 적용한 기능 |
|---|---|
| 원문·코드 탐색 | `locate REF '문자열'`로 검색한 파일 안의 정의·호출부 위치를 찾고, `read REF --start-line N --end-line M`으로 조각 경계를 넘어 읽기. MCP에도 같은 기능 제공. |
| 선택형 의미검색 | `search '질문' --collection NAME --semantic` 또는 MCP `semantic=true`. 별도로 준비한 로컬 모델·문서 인덱스가 있을 때만 실행. 반환한 문자 위치로 원문 읽기. |

파일 안 탐색은 문자열 검색입니다. 언어 서버의 심벌 분석이나 자동 호출 그래프는
구현하지 않았습니다. 검색에서 받은 현재 ref의 파일만 열고, 접근 정책과 원본
해시를 확인합니다. 절대 줄 번호와 들여쓰기를 보존합니다. PDF·Office는 기존
조각·페이지 읽기를 씁니다. 위치 찾기도 원문 읽기 횟수에 포함하며, 보통 한 작업에
두 도구를 합쳐 최대 세 번의 1,200바이트 읽기를 권장합니다.

의미검색에는 원래 512토큰 입력 제한이 있었습니다. 이번에는 출처 정보를 포함한
짧은 읽기에 맞도록 본문을 최대 512바이트로 나누고 겹침 길이를 조절했습니다.
파일당 서로 다른 조각 두 개까지 반환하고, 각 후보에 정확한 문자 위치를 넣었습니다.
출처 경로가 길면 여전히 이어 읽기가 필요할 수 있습니다. 기존 인덱스도 읽을 수
있으며, 같은 문서 범위로 다시 만들면 새 분할 방식이 적용됩니다.

실제 로컬 모델 검증에서는 자료 여덟 개와 질문 여섯 개를 추론 전에 고정했습니다.
기존에 준비한 multilingual E5 모델과 FastEmbed 환경을 그대로 사용했습니다.
정답 별칭·가중치·질문별 규칙을 엔진에 추가하지 않았습니다.

| 여섯 질문의 확인 항목 | 기존 토큰 기준 분할 | 새 바이트 기준 분할 |
|---|---:|---:|
| 의미검색 상위 세 후보에 목표 파일 포함 | 5/6 | 5/6 |
| 후보 중 하나의 첫 읽기에서 답 문장 확인 | 3/6 | 5/6 |
| 자료 여덟 개의 임베딩 구간 수 | 22 | 61 |

이 비교는 양쪽 모두 새 후보·읽기 정책을 사용하고 분할 방식만 바꿨습니다.
구버전 엔진 전체와의 비교는 아닙니다. 새 방식의 읽기는 최대 936바이트였고
이어 읽기가 필요하지 않았습니다. 단어 검색의 목표 파일 포함은 3/6이었고,
의미검색이 두 사례를 더 찾았습니다. 영어로 질문한 한국어 알림 시간 문서는
여전히 찾지 못했습니다. 작은 기능 점검이며 일반 답변 정확도나 새 벤치마크
점수를 뜻하지 않습니다. 구간이 늘어 인덱스 크기와 생성 작업도 증가합니다.

단위 테스트 133개, 설치된 CLI·MCP와 분리된 wheel 설치로 기능을 검증했습니다.
변경된 원본·정책 차단, 한국어 바이트 예산, 조각 경계, 원문 전체의 분할 범위,
의미검색 접근 범위를 확인합니다. 공개 코드의 `_read_text` 정의와 호출부도
실제 줄 번호로 확인합니다. 구독 Codex의 실제 도구 호출 점검은 도구 실행 전에
호스트 승인 정책에 막혔으므로, 에이전트 작업 성공으로 계산하지 않았습니다.

의미검색은 명시적으로 선택할 때만 사용합니다. 유사도는 확신도가 아니며,
기억 카드 의미검색·자동 후보 결합·그래프 DB·모델 학습은 추가하지 않았습니다.
[설정과 제한](semantic-pilot.md), [영문 검증 기록](navigation-and-semantic.md)을
참고하세요. 운영 자료와 실행 로그는 공개 저장소에 포함하지 않습니다.
